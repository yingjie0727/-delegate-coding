本包脚本的离线测试共 76 项：75 项通过，1 项 DPAPI 测试因受限 Windows 用户未加载相应用户配置而跳过。离线测试使用假模型和假密钥，不等同于厂商真实兼容性验证。真实 API 小任务由用户自己的 Windows 终端发起；GPT 独立检查没有读取密钥。

此次分享包还检查了源码语法、本地文档链接、文件白名单、个人路径/密钥样式、文件哈希和压缩包完整性。官方 quick_validate.py 因开发机可用 Python 缺少 PyYAML 未运行，没有把它标记为通过。

本轮主要 Windows 修复：独立配置必须声明本机沙箱后端；后端纳入任务配置指纹；独立 codex-home 放在私有 profile 下；增加不调用 API 的环境检查。没有关闭沙箱，也没有更改主 Codex 登录或模型菜单。

当前 API 实测仍需要用户启动一次本机入口。安装 Skill 并不会自动增加 MCP 服务、原生模型菜单或桌面软件控制权限。执行器报告完成后，GPT 仍要检查实际差异、受保护文件和测试。

### WorkBuddy 5.11.3 文件往返

2026-11-21，Codex 通过桌面操作定位并前置 WorkBuddy，在空白任务页输入交接文字。一次粘贴后输入框仍为空，改用原生文本输入后完整内容可见。单击发送后，在新会话中核对任务编号，再记录 `sent_verified`。WorkBuddy 领取任务并写回文件、提交对应报告。

第一轮返回了正确的输入哈希，任务要求的是逐字符复制，因而退回。第二轮明确要求原样复制。独立检查确认任务编号和输入文本逐字符匹配、输入文件未变化、工作目录仅增加预期结果文件，最终状态为 `accepted`。

此测试覆盖了当前本机桌面上的发送、领取、文件回传与验收。更换设备或桌面操作环境时可按[桌面操作说明](../skills/delegate-coding/references/desktop-control.md)重新验证。

### CodeBuddy CLI 2.185.0

2026-11-21，`-p` 非交互调用准确返回随机文本。独立的文件探针启用 `Read` 和 `Write`，CLI 读取文件后按原文写回。

随后使用本仓库的 `create --route cli` 和 `run-cli` 在干净的 Git 工作区执行一次真实任务。CodeBuddy 提交结构化报告。GPT 独立确认输入和输出逐字节相同、Git 只出现预期的新文件、HEAD 与暂存区未变，最终状态为 `accepted`。

CLI 路线的调用与验收步骤见 [CodeBuddy CLI 路线](../skills/delegate-coding/references/cli-route.md)。
