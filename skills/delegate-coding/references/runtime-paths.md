# 首次配置后记住本机路径

让 GPT 定位、验证并记录运行位置，用户无需在每项任务中重复查找 API 执行器的绝对路径。本文件提供通用方法，不包含开发机的个人路径。

## 定位

1. 从实际加载的 `SKILL.md` 所在目录解析随包脚本：`scripts/delegate.py`、`scripts/api_worker.py` 和 `scripts/check_executor.py`。不要把当前工作目录误当作 Skill 目录，也不要要求用户手工定位这些随包文件。
2. 查找本机 Python 3.11+。优先复用用户已经配置且能正常运行的解释器，核对版本与实际位置。不要自动安装或替换用户的 Python。
3. 查找用户配置的 Codex CLI，或使用系统 PATH 中可验证的 `codex`。Windows 桌面版的安装位置还可在 `%LOCALAPPDATA%\OpenAI\Codex\bin` 的版本子目录中检查。选定位置后运行离线版本/帮助检查；不要从本仓库复制或打包应用二进制。
4. 复用用户选定的 API profile，并确认其公开配置。profile 必须放在实现工作区之外。没有配置时，按 [API 路线](api-route.md) 初始化，不把其他厂商或其他模型当作隐式替代。

这些步骤不需要读取密钥文件、调用真实模型或展示环境变量中的凭据。

## 记录

配置并验证后，向用户说明将保存哪些非秘密位置；在本机已安装的 Skill 中添加一个明确标为“仅本机”的区段，记录：

| 记录项 | 内容 |
| --- | --- |
| Python | 已验证的解释器绝对路径 |
| Codex CLI | 已验证的 CLI 入口绝对路径 |
| 任务和 API 脚本 | 由实际 Skill 目录解析的三个脚本位置 |
| API profile | 公开配置和加密凭据所在的私有目录位置 |
| 校验时间与范围 | 验证到哪一步，是否仍需用户启动本机入口 |

只写入路径和公开配置摘要，不记录 API Key、登录令牌、密文内容或任务私有信息。读取记录不能代替检查实际文件是否存在。安装目录不可写时，准备好具体修改并通过当前环境允许的权限流程写入；不要更改系统权限或要求用户每次重新输入整串路径。

本机路径设置不改变任务授权：执行器仍需按当前任务创建、领取、报告和验收。用户明确换路线、模型或 profile 时，以当前要求为准。

## 后续使用和升级

- 后续由 GPT 读取已记录的位置，按实际项目准备任务。首次使用新项目或更换 CLI、后端、权限后，先完成不调用模型的 Windows 执行环境检查。
- 应用更新导致 CLI 旧路径消失时，重新定位已安装版本、核对版本并检查环境，再更新本机记录。不因旧路径失效就默认让用户再次查找。
- 若脚本目录或 profile 被用户移动，确认新位置后更新记录，不擅自迁移或复制凭据。
- 更新 Skill 前保留用户的“仅本机”区段与其他自定义修改。发布到 GitHub 时去掉实际个人路径，使用仓库通用源码；不要直接把带本机区段的安装副本上传。

记住路径能省去重复输入，但不会自动解决不同 Windows 身份之间的 DPAPI 解密限制。如果当前 Codex 沙箱不能使用用户凭据，由 GPT 基于已记录的路径准备本机入口，用户启动后自动执行，再由 GPT 验收。不要把路径配置完成表述为全自动派发已经验证。
